# d·camp 프리스크리닝 엔진 v4 — 재설계

v1~v3 은 "사실 → 레벨 → 가중평균 → Tier"의 **점수 계산부**를 결정적으로 만들고
(v2), 불확실성을 구간으로 전파(v3)했다. v4 는 그 위에서 **입력·라우팅·게이트·
불확실성 검출**을 재설계한다 — 대규모 자동 평가에서 드러난 문제(사람 검토·정보
부족 과다, 조용한 오분류)를 구조적으로 고친다.

가중치(Traction/TRL 40·Team 30·Market/양산 20·Moat/고객 10)는 **변경하지 않았다.**

## 무엇이 바뀌었나 — 6가지

| # | v3까지의 문제 | v4 수정 | 구현 |
|---|---|---|---|
| 1 | 키워드 라우팅이 tech 태그 하나로 오분류하고, 조용히 확신 | **다신호 가중 라우터 + 자기불확실성 플래그** | `router_v4.py` |
| 2 | 스테이지 이탈을 뭉뚱그림(시리즈A와 시리즈D가 같은 '사람 검토') | **스테이지 3분할** (경계/스케일업/타깃) | `gate_v4.py` |
| 3 | 빈 DB 행을 '판정 불가'로 엔진 탓처럼 표기 | **입력 상태 분리** (대상외/자료요청/정상) | `gate_v4.py` |
| 4 | Team `확인 필요`가 사람 검토의 주범 | **자동 창업자·트랙션 보강 단계(Step 1.5)** | `levels_enriched.py` |
| 5 | 사실→레벨이 단일 분류자 판단(κ 0.59) | **앙상블 분류 + 자동 `판정 불안정`** | `agreement.py` 인프라 |
| 6 | 컷오프가 미검증(확정 불합격 2개사) | **프록시 라벨 검증 하니스** | 아래 §6 |

---

## 1. 다신호 가중 라우터 (`router_v4`)

**전**: 섹터/기술/소개를 순서대로 훑어 **첫 매칭 키워드**로 트랙 결정. DB 의 tech
태그가 틀리면(예: 메텍홀딩스 tech='소프트웨어', 실제=메탄 캡슐 HW) 그대로 오분류.

**후**: bio·hw·sw 3축에 **가중 점수**를 합산한다. 신뢰 가중은 사업 실체에 가까운
순서로 — **desc(1.0) > tech 태그(0.7) > 섹터(0.5) > 영문명(0.4)**. 최상위 트랙과
2위의 점수 차가 기준(2.0) 미만이면 `라우팅 불안정`으로 표시해 **점수화 이전에 사람
확인**으로 보낸다. 즉 애매하면 조용히 틀리지 않고 스스로 손을 든다.

- 바이오 오분류 차단: `디지털 치료제·진단·의료기기·모니터링·플랫폼·SW`가 있으면
  바이오 점수 0 (IndieBio 는 생물학적 치료제 전용).

## 2. 스테이지 3분할 게이트 (`gate_v4`)

**전**: 시리즈A 이상 → 500 전부 `사람 검토`, HAX 전부 `탈락`. 시리즈A(시드 인접)와
시리즈D(완전 스케일업)가 한 버킷.

**후**:

| 스테이지 | v4 판정 | 뜻 |
|---|---|---|
| 프리시드~시드 초기 | **점수화 대상** | 프로그램 타깃 |
| 프리A~시리즈A | **사람 검토(경계)** | 아직 지원 여지 |
| 시리즈B 이상/IPO/M&A | **스케일업 트랙 안내** | 탈락이 아니라 '단계가 다름' → 별도 큐 |

효과(전체 DB): 사람 검토 **468 → 244**(반감), 게이트 탈락 225 → 0(스케일업 안내로
재분류 — 좋은 회사를 '탈락'이라 부르지 않는다).

## 3. 입력 상태 분리

**전**: 빈 행도 '판정 불가'. 엔진 결함처럼 보인다.

**후**: **대상외(입력 없음)** / **자료 요청(신호 약함·스테이지 미상)** / **정상**으로
분리. 빈 DB 행(대부분 하위펀드 CRM 스텁)은 '평가 대상외'로 명시 — 엔진이 판정을
안 하는 게 아니라 **판정할 입력이 없는 것**임을 드러낸다.

## 4. 자동 데이터 보강 단계 (Step 1.5)

Team `확인 필요`가 v3 구간을 넓혀 사람 검토를 유발하는 최대 원인이었다. v4 는
점수화 이전에 **창업자 이력·최신 트랙션을 자동 재검색해 실증이 확인된 축만** 채운다
(못 찾으면 null 유지 — 지어내지 않음). 규칙을 라벨에 맞추는 암기가 아니라 **입력
완결성**을 높이는 자동화다. 팩트시트 있는 102개사에서 사람 검토 78→74, 확정 추천
8→10 로 실측(`levels_enriched.py`). 실제 운영에선 지원서 덱·CV 가 이 단계를 대체한다.

## 5. 앙상블 분류 + 자동 불확실성 검출

사실→레벨은 여전히 판단이며 재현율 74%(κ 0.59)다. v4 는 각 축을 **여러 독립
분류자**가 매기고, 불일치하면 자동으로 `판정 불안정`으로 표시해 v3 구간에 전파한다.
low-confidence 표시가 실제 불일치를 정밀도 65%로 예측함이 이미 측정됐다
(`agreement.py`). 이로써 엔진이 자기가 모르는 축을 **스스로 감지**한다.

## 6. 프록시 라벨 검증 하니스

확정 불합격 표본이 2개사뿐이라 컷오프(4.00/3.25/2.50)를 영구히 검증 못 했다. v4 는
디캠프 **Type1 패밀리사(재단이 실제 투자·입주시킨 기업)**를 약한 양성 신호로 써서,
엔진의 `확정 추천`이 패밀리사와 상관하는지 **검증**한다(컷오프를 여기 맞춰 튜닝하는
것이 아니라 상관을 관찰). 진짜 보정은 500/HAX 추천 후 합불 라벨이 확보돼야 가능하며,
이 하니스는 그 자리를 만들어 둔 것이다.

---

## 라벨 비의존 원칙 (유지)

라우팅 키워드·스테이지 컷은 전부 **프로그램 공식 정의**(HAX=하드웨어/기후/로보틱스,
바이오 치료제=IndieBio, 500·HAX=프리시드~시드)에서 나온 것이지 합불 분포에 맞춘
것이 아니다. WEIGHTS 불변, 컷오프 라벨 튜닝 없음.

## 남은 한계 (정직하게)

1. 키워드 라우터는 여전히 근사다 — v4 는 틀릴 때 **스스로 플래그**하는 것이 개선점
   이지, 항상 맞히는 게 아니다.
2. 대규모 단계에서 4축 점수는 못 낸다(1줄 소개 한계) — 점수는 팩트시트 있는
   소표본에서만.
3. 정밀도·특이도는 여전히 미측정(진짜 불합격 라벨 필요).
