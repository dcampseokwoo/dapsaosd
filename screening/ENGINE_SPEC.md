# d·camp 프리스크리닝 엔진 — 구조 설계 (현행, v4 기준)

> 한 줄 요약: **문서·설문 파싱 → 스테이지 분류 → 프로그램 라우팅(다신호) → 하드
> 게이트(3분할) → 신뢰성 스캔 → 자동 데이터 보강 → AI는 사실만 분류하고 룰이 점수
> 계산 → 불확실성을 구간으로 전파 → Quality × Fit 2축으로 Tier·조치 판정.**
>
> 핵심 불변: **AI는 점수를 매기지 않는다. 사실만 분류한다. 점수는 고정 룰 테이블이
> 계산한다.** 가중치(트랙션/TRL 40·팀 30·시장/양산 20·해자/고객 10)는 디캠프 내부
> 루브릭이라 건드리지 않는다.

| 층 | 내용 | 검증 상태 |

## 0.5 v7 재설계 — 업종/분야 분리 · 사람검토 폐지 · 새 DB (최신)

매니저·실무 피드백을 반영해 크게 다시 짰다. 밑바탕은 v6.1의 config SSOT(프로그램
기준을 `programs.py` 한 곳에 선언 → 프로그램 교체 시 그곳만 수정)를 유지하고, 그 위에:

| 변경 | 무엇 | 파일 |
|---|---|---|
| **① 업종 ≠ 분야** | 업종(CB 40그룹)은 거칠다 — 'Hardware'에 로보틱스·반도체와 소매기술·화상회의가, 'Financial Services'에 결제·대출·보험이 섞인다. 그래서 라우팅·탈락은 **분야**(1줄 소개·기술로 세밀 판정)가 authoritative, 업종은 거친 prior/폴백. **업종≠분야 불일치(⚠)는 그 자체가 검토 신호.** | `sectors.py`(`field_of`, `CB_GROUP`) |
| **② 사람검토 폐지** | 확정 탈락이 아닌 모든 것을 **메일 대상**으로 흡수(경계·설문필요·점수화가능·라우팅접전 전부). 애매하다고 붙잡아두면 아무 일도 안 일어난다. 메일 유형(내부검토·지원 / 설문·자료요청 / 자가진단·보완)만 세분. | `disqualifiers.py`, `engine_programs.py` |
| **③ 새 DB(Ver.26.01) 재추출** | 이전 `gbd_full.json`은 빈 행이 42% 섞여 '대상외'가 과다했다(추출 문제). 새 파일은 업종·기술·스테이지·소개가 99% 채워져 **대상외가 사라지고 스테이지 이탈(시리즈B+/IPO/M&A) 확정 탈락이 제대로 발동**한다. | `data/gbd_v26.json` |

**판정 구조 (2갈래 + 부수)**: 🔴 확정 탈락 / 🟢 메일 대상 / 🔵 IndieBio 리퍼럴 / ⚪ 대상외(정보 공란, 이제 드묾).

**확정 탈락 = 확인된 부적합만**: 스테이지 이탈(시리즈B+ 양 트랙·HAX 시리즈A+), 분야
부적합(HAX 제외 분야: 핀테크·크립토·커머스·보안), 확인된 언어불가·제품없음. 언어·제품은
덱/설문이 와야 확인되므로 그전엔 메일(설문)로 남긴다. **하드웨어 문맥에 SW 단어가
섞여도 우선 분야가 함께 잡히면 오탈락하지 않음**(예: "결제 단말 로봇 하드웨어" → HAX 유지).

**트랙션(500) 정의**: 시장이 실제 반응한 증거 — 유료고객 수·매출(MRR/ARR)·MoM
성장률·리텐션, B2B는 계약/PO/LOI. 1줄 소개론 측정 불가 → 대규모 자동단계엔 트랙션
점수를 내지 않고 덱·설문 있는 기업만 채점.

**대규모 실행 결과(3,424개사)**: 🔴 확정 탈락 1,335(대부분 스테이지 이탈) · 🟢 메일
대상 ~1,961 · 🔵 IndieBio 128 · ⚪ 대상외 0. 산출물 `gbd_auto_eval_v7.xlsx`(500/HAX
엔진 시트에 업종·분야 2열 + 메일 유형).

**불변**: WEIGHTS·컷오프 그대로. 트랙 매핑은 프로그램 공식 정의에서 왔고 합불 분포
튜닝이 아니다. 테스트 103개 통과.

## 1. 기입해야 하는 정보

- **필수 문서**
  - Pitch deck (deeptech deck 템플릿 준수)
  - 공동창업자 전원 LinkedIn / CV
  - Prior fundraising history — 라운드별 (금액 / 성격[엔젤·VC·정부과제] / 시기)
- **구조화 설문 (문서로 확인 불가한 것)**
  - 풀타임·겸직 여부 / 이주 가능 여부 / 캡테이블 / 비즈니스 모델 자기분류 /
    최근 3~6개월 MRR·유료 고객 수
- **선택 제출**: 계약서·PO·LOI 등 증빙 (있으면 **증거 등급 상향**)
- **증거 등급 규칙(신규 명문화 §4)**: `증빙(계약/PO/LOI)` > `문서 명시` >
  `설문 자기신고` > `추정`. **`문서 명시` 미달이면 그 축에 레벨을 매기지 않고
  `확인 필요`로 두고 가중평균에서 제외 후 재정규화.** ← 정보 부재를 L1이나 중간값
  L3로 채우는 것 금지(v1 최대 결함).
- **이탈 방지 2단계 진단**
  - 1차: 덱 + CV만으로 **간이 진단**(다수 축 `확인 필요` → v3 구간이 넓음)
  - 2차: 설문·증빙 추가 시 **정밀 진단**(구간이 좁아지며 확정 판정 비율 급증)
  - 실측: `확인 필요` 축을 채우면 확정 판정 2/10 → 9/10 (구간 폭의 89%가 자료 부재 탓)

## 2. 평가 흐름 (8단계 — 자동보강 신설)

```
파싱 → 스테이지 분류 → 라우팅 → 하드 게이트 → 신뢰성 스캔
      → [Step 1.5 자동 데이터 보강] → 채점(사실→레벨→룰이 점수)
      → 불확실성 구간 전파 → Quality × Fit → Tier·조치
```

### 2-1. 스테이지 분류
- 창업 시점·펀딩 이력·매출 규모로 **프리시드 / 시드 초기 / 시드 후기 / A 이후** 분류.
- 이후 모든 채점·비교·벤치마크는 **같은 밴드 안에서만.**
- 이유: 누적량 기준이면 스테이지 높은 회사가 항상 우위 → 왜곡. 특히 500/HAX에선
  높은 스테이지는 우위가 아니라 **게이트아웃 대상.**

### 2-2. 라우팅 (v4 다신호 + v6 두 엔진 분리·양쪽 평가)
- **전(v1~v3)**: 첫 매칭 키워드로 트랙 결정 → tech 태그 하나 틀리면 조용히 오분류.
- **v4 다신호**: bio·hw·sw 3축에 **가중 점수 합산**, 신뢰 가중은 사업 실체 순 —
  **사업 소개(1.0) > 기술 태그(0.7) > 섹터(0.5) > 영문명(0.4).**
  - 하드테크 → HAX / 테크이네이블드·SW → 500 / 바이오 **치료제·신약** → SOSV
    IndieBio 안내(진단·의료기기·디지털치료제는 라우팅 X).
- **v6 — 500과 HAX는 별개 엔진**(`engine_programs.PROGRAMS`): 축·스테이지 정책·
  확정 탈락 기준·섹터 정책이 프로그램별로 완전 분리. 출력도 **트랙별 시트**로 분리.
  - **애매하면 양쪽 다 평가(dual-run)**: 라우팅 신호가 접전이면 사람에게 미루지 않고
    500·HAX 두 엔진에 모두 통과시킨다 → 한쪽만 통과하면 **자동 확정**, 둘 다 통과하면
    **`양 프로그램 후보`**(부담 아닌 긍정), 둘 다 탈락하면 확정 탈락. → 라우팅 미결
    버킷 0.
  - **크로스 프로그램 리퍼럴**: 한 프로그램에서 탈락해도 다른 프로그램 후보면
    `타 프로그램 후보`로 넘긴다(막다른 탈락을 라우팅 정보로). 예: HAX 스테이지·섹터
    탈락 → 500 은 섹터 무관·시리즈A 수용이라 후보(catch-all).

### 2-3. 하드 게이트 (v5 — 확정 탈락 디스퀄리파이어 + 3분할)
판정 = **확정 탈락** / 사람 검토 / 조건부(설문) / 라우팅 확인 / 점수화 / 자료요청 / 대상외

**핵심 원칙(v5): "확실히 아닌 건 확실히 탈락시킨다."** 프로그램이 **절대 waive
하지 않는 기준**에 **확인된 사실**이 걸리면 즉시 `확정 탈락`(사유 명시). 스크리너의
본질은 거르는 것이므로, 부적합을 물렁하게 유보하지 않고 결정적으로 떨궈 운영자가
큐를 비운다. (v4의 '스케일업 안내' 물렁 유보는 **철회.**)

- **확정 탈락 디스퀄리파이어 6종** (`disqualifiers.py`):
  1. **스테이지 이탈** — 시리즈B+ (양 트랙) / **HAX는 시리즈A도 이탈**(프리시드~시드 전용)
  2. **섹터 부적합** — HAX 제외 섹터(핀테크·크립토·보안·이커머스·순수SW)
  3. **언어** — C레벨 영어 불가 **확인**(영어 전용 프로그램)
  4. **제품** — 동작 프로토타입/실물 없음 **확인**
  5. **커밋** — 풀타임/이주 거부 **확인**(500)
  6. **HAX 오너십** — 프라이스드 라운드/지분 10% 수용 불가
- **확인된 것만 탈락** — 3~6은 설문·덱이 있어야 확인된다. **미확인이면 추측으로
  떨구지 않고 `조건부(설문 필요)`로 두고 점수화는 진행.** ("모르는 것"으로 탈락 금지.)
- **경계는 사람 검토** — 500 시리즈A(시드 스위트스폿 상단)는 확정 탈락이 아니라 경계
  → 사람 검토.
- **입력 상태 분리**: 대상외(입력 없음) / 자료 요청(신호·스테이지 미상) / 정상 —
  빈 입력을 '엔진 판정 불가'처럼 표기하지 않는다.

> DB 대규모 단계에는 설문·덱이 없어 **스테이지·섹터만 확정 탈락**을 발동한다(언어·
> 제품·커밋은 조건부). 실제 지원서가 들어오면 나머지 디스퀄리파이어가 활성화된다.
> 실측(DB 3,424): 확정 탈락 389(스테이지 이탈 385 + 섹터 부적합 10), 사람 검토 187.

### 2-4. 신뢰성 스캔 (채점 전 실행)
- 문서 간 수치 불일치 / 산술·환율 오류 / **고객 vs 위시리스트** / 자기 인용 / 과장 표현.
- 결과 정상 / 경계 / **붕괴** → 붕괴면 주축(500=트랙션 / HAX=TRL) **L2 상한.**

### 2-5. Step 1.5 — 자동 데이터 보강 (신규)
- 채점 전에, `확인 필요` 축(특히 **팀** — 개인 창업자 이력이 덱에 없을 때)을
  **창업자 이력·최신 트랙션 자동 재검색**으로 채운다. **실증이 확인된 축만** 채우고
  못 찾으면 null 유지(지어내지 않음).
- 규칙을 라벨에 맞추는 암기가 아니라 **입력 완결성**을 높이는 자동화.
- 실측(팩트시트 102개사): 사람 검토 78→74, 확정 추천 8→10.

### 2-6. 채점 (사실 → 레벨 → 룰이 점수)
- 500 = 트랙션 40·팀 30·시장 20·해자 10 / HAX = TRL 40·팀 30·양산경로 20·고객 10.
- **누적량 아닌 속도·비율 지표**: MoM 성장률·첫 유료고객까지 걸린 시간·조달액 대비
  트랙션(자본 효율). "얼마나 쌓았나"가 아니라 "얼마나 빨리 가나".
- **스테이지 밴드별 레벨표(§3)**: v1의 절대표(프리시드가 L2 상한에 갇힘)를 폐기,
  밴드 안에서의 최고 속도를 L5로 재정의.
- **판별 질문 명문화(§3·§4, 재측정에서 실제 갈린 경계)**: 예)
  - L2↔L3: *외부 사용이 사실로 명시됐는가?* / L3↔L4: *돈이 실제로 이동했는가?*
  - 팀 증거 = **개인 단위 경력 사실**만(회사의 조달·프로그램 선발 이력은 팀 근거 아님).
  - 시장 상향 금지: 덱 없이 시장 규모로 L3+ 금지.
- **가중합만 쓰지 않음**: 트랙 핵심축(500=트랙션·팀 / HAX=TRL·팀) L1이면 상한 C 강등.
  B2B 화폐 증거 0이면 트랙션 상한. **커버리지 < 60%면 Tier 대신 `판정 보류`(탈락 아님).**

### 2-7. 불확실성 구간 전파 (v3 — Tier 하나 대신 구간)
- `확인 필요` 축 → 가능 범위 L1~L5 / 경계 판정 축 → 인접 대안까지 / 확정 축 → 고정.
- 하한 = Σ(하한×가중치), 상한 = Σ(상한×가중치).
- 구간 전체가 추천선(3.25) 이상 → **확정 추천** / 미만 → **확정 비추천** /
  걸치면 → **사람 검토**(엔진이 단정하지 않는다).

### 2-8. Tier·조치
- Tier: A 추천 / B 확인 후 추천 / C 보완 후 재도전 / D 부적합.
- v3 구역 × Fit → 조치(추천 진행 / 조건부 / 설문·증빙 요청 / 타 프로그램 / 비추천).

## 3. Quality 와 별도로 Fit 판정
(좋은 회사라고 500이 좋아할 회사는 아님 — 두 축 분리 표기.)

- **Quality** = 채점 결과(회사 자체가 얼마나 좋은가).
- **Fit** = 프로그램 적합성 **규칙표 6신호 가중합**(정성 판단 → 결정성 확보):
  스테이지 밴드 정합 / 섹터 테마 정합 / 유사 합격 사례 존재 / **조달 그래머(VC 트랙
  vs 정부 TIPS→코스닥)** / 세일즈 사이클 4개월 정합 / **모멘텀(최근 24개월 진전)**.
  - yes → +가중치 / no → −가중치 / **unknown → 0(모르는 걸 no로 바꾸지 않음).**
- 출력: "Quality 높음 × Fit 낮음 → 타 프로그램 추천" 같은 2차원 판단.

## 5. 점수 안 흔들리게 하는 법 (핵심 설계 결정)
**AI는 점수를 매기지 않는다. 사실만 판정한다.**

- **AI 역할**: "유료 고객 있나? 예/아니오" 같은 **사실 확인만** → 점수는 고정 룰
  테이블(코드)이 계산 → 같은 답이면 같은 점수. (레벨→Tier 구간은 테스트로 강제.)
- 0–10점 대신 **5단계 레벨.**
- **⚠ 앵커 9개사 기준점(SECA=L4 등)은 실제로 미제공** → 페어와이즈 비교 불가.
  대신 **판별 질문(§3·§4)**으로 레벨 경계를 명문화하고, 애매하면 낮은 쪽 부여 +
  `판정 불안정` 표기(대안 레벨 기록 → v3가 구간으로 전파).
- **재현성을 실제로 측정함(신규, 가장 큰 발견)**: 사실→레벨 분류를 **dataset을 본 적
  없는 독립 평가자**가 블라인드로 재분류 → 완전 일치 60%·인접 71%·**κ 0.38**.
  §3·§4 판별 질문 보강 후 74%·**κ 0.59.** ← "같은 사실이면 같은 점수"의 **앞 절반
  (사실→레벨)이 그대로는 재현 안 됨**을 처음으로 드러냄. 이 구간의 불일치는 v3 구간·
  `판정 불안정`으로 출력에 노출하는 것이 현재의 정직한 처리.
- **3회 실행 다수결 → 앙상블 분류**: 각 축을 여러 독립 분류자가 매기고 불일치하면
  자동 `판정 불안정` → v3 구간 전파. low-confidence 표시가 실제 불일치를 정밀도
  65%로 예측함이 실측됨.
- **품질 게이트**: 규칙 수정 때마다 **불일치했던 축만 재분류해 일치율이 실제로
  올랐는지 측정.** 안 오르면 되돌린다(작업 2-3). 기존 회귀 테스트 54건 유지.

## 7. 운영 원칙
- **평가는 전 과정 AI 자동**: 파싱→게이트→신뢰성→보강→채점→구간→Tier까지 AI+룰.
  자가진단용은 사람 개입 0%.
  - 사람 개입은 평가가 아닌 **2곳뿐**: ① 서류에 답이 없어 `확인 필요` 플래그가 뜬
    항목의 사실 확인 ② 500 추천 발송 전 최종 승인(디캠프 이름 책임 절차).
  - + v4 신규: **`라우팅 불안정`·`판정 불안정` 플래그** 항목은 사람이 사실만 보조.
  - 승인 단계는 캘리브레이션 쌓이면 축소(한시적 안전장치).
- **불명 = 0점이 아니다**: 정보 없으면 감점이 아니라 `확인 필요` 플래그.
- **스테이지 밴드 분리**: 누적 데이터·비교·벤치마크는 반드시 동일 스테이지끼리.
- **게이밍 방어**: 재제출 시 diff 표시 + 증빙 없는 수치 개선 경고.
- **캘리브레이션**: 확정 불합격 표본 2개사뿐 → 정밀도·특이도 미측정. 컷오프
  (4.00/3.25/2.50)는 보충값. 실제 합불이 쌓일 때마다 보정하며, **유사 사례 매칭·
  GBD DB가 합격자 데이터 수집 채널** 역할.
  - **프록시 라벨 검증(v4 신규)**: Type1 패밀리사(재단 실투자)를 약한 양성 신호로
    써서 `확정 추천`과의 상관을 관찰(컷오프를 여기 맞춰 튜닝하는 것이 아니라 검증).
- **평가 항목(500/SOSV Criteria)**: 관심 섹터 + 비즈니스 모델 Fit / 투자 이력 /
  Team·Founder 이력 / C레벨 영어.
